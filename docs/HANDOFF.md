# 项目交接检查表

交接目的：使新的维护人员能够独立阅读代码、部署测试服务、理解安全边界、执行 CI 与版本发布，并继续处理已记录的任务。

## 1. 接手阅读与环境准备

- [ ] 阅读 [README](../README.md) 与 [文档索引](README.md)，确认项目的实际范围。
- [ ] 阅读 [项目台账](PROJECT_LEDGER.md)，明确当前 `v0.3.1` 的完成情况和未完成事项。
- [ ] 阅读 [系统架构](ARCHITECTURE.md) 和 [协议兼容性](PROTOCOL_COMPATIBILITY.md)，找到对应代码模块。
- [ ] 阅读 [安全设计](SECURITY_MODEL.md)，确认私用 root 与公用 PAM 的权限区别及虚拟文件登录风险。
- [ ] 在专用开发环境配置 Python 与依赖，执行 [开发与测试](DEVELOPMENT.md) 中的相应测试。
- [ ] 确认能够访问 GitHub 仓库、Actions 日志与 Release 页面。

## 2. 需要由现任维护者交接的运行资料

| 资料 | 需要核实的内容 | 保存方式 |
| --- | --- | --- |
| 仓库与 CI | GitHub 仓库写入权限、工作流管理权限、发布权限和当前保护规则 | 组织权限管理 |
| 设备及服务器清单 | 测试/生产设备、操作系统、CPU 架构、固件版本及网络位置 | 受控资产记录 |
| hbbs/hbbr | 服务端版本、DNS、端口、TLS/加密要求、连接限制和维护负责人 | 受控运维记录 |
| 配置与密钥 | `config.toml`、`identity_file`、`password_file` 和中继密钥的存放位置及备份负责人 | 加密的受限存储 |
| PAM 与用户管理 | `pam_service`、允许访问的用户范围、账号关闭和密码更新流程 | 组织的系统管理记录 |
| OpenWrt 部署 | 安装包版本、`procd` 状态、存储及内存限制、升级恢复方式 | 设备维护记录 |
| 安全事件与变更 | 需要关注的安全问题、实际部署变更及处理联系人 | 受限维护系统 |

本文件只列出所需资料种类，不登记任何真实密码、身份私钥或生产服务器地址。

## 3. 接手人员首次应完成的操作

- [ ] 获取并检查最新 `main` 与最近一次 Release 的版本对应关系。
- [ ] 执行 `python scripts/check_docs.py`，确认文档链接与版本信息一致。
- [ ] 运行适合其环境的测试，查看 GitHub Actions 的历史测试范围。
- [ ] 在独立设备或容器中部署私用模式，检查连接密码、终端和文件访问权限。
- [ ] 如需维护公用模式，使用专用测试用户检查 PAM 登录、工作进程身份和未认证文件操作的限制。
- [ ] 如需维护 OpenWrt，在官方容器及实际目标 CPU 架构上验证安装和恢复。
- [ ] 按 [运维文档](OPERATIONS.md) 检查配置与身份备份能否恢复。
- [ ] 核实 [台账待办事项](PROJECT_LEDGER.md) 的负责人和处理顺序。

## 4. 变更与发布前检查

- [ ] 已确认功能行为与安全边界，包括出错或断开连接后的状态。
- [ ] 已针对更改模块增加或更新自动化测试。
- [ ] 已执行对应系统的测试，并记录真实环境与模拟环境的区别。
- [ ] 已更新相关文档和开发台账。
- [ ] 已确认提交不含真实凭据、环境密钥和私人设备信息。
- [ ] 已按 [发布说明](RELEASING.md) 更新版本号、发布说明并核查构建结果。

## 5. 当前仍需要验证的事项

目前仍须完成官方 GUI 与真实 hbbs/hbbr 互操作测试，检查端口转发真实双向传输，以及评估 OpenWrt 其他 CPU 架构与设备资源占用。有关优先级和具体完成条件见 [项目台账](PROJECT_LEDGER.md)。接手人员应根据实际部署需求决定工作顺序，并将测试结果补入对应文档。

交接结束时，新的维护人员应能够独立完成测试环境部署、主要模块定位、CI 结果判断和新版本发布，并清楚知道哪些兼容性结论仍需实际验证。
