# 认证、权限与安全设计

本文件面向维护人员。使用者首先阅读 [SECURITY.md](../SECURITY.md)，协议和程序模块参见 [系统架构](ARCHITECTURE.md)。

## 1. 信任关系

1. **设备身份。** 服务端使用设备 Ed25519 身份私钥签名握手信息。独立 CLI 在发送凭据前按 `--peer-key` 验证设备公钥及设备 ID。
2. **传输保密。** 客户端与被控端协商会话密钥，之后使用加密的 RustDesk 消息收发认证信息。hbbs/hbbr 仅用于协调与中继，不应因此获得 PAM 密码。
3. **RustDesk 连接密码。** 私用模式必须设置。公用模式可选，用于在 PAM 之前增加共享密码检查。其验证采用 RustDesk 标准挑战响应。
4. **Linux 身份。** 公用模式的终端与文件传输分别进行 PAM 验证。会话中的账户身份由服务端选择，客户端提供的显示名称或 IP 地址没有授权效力。
5. **系统权限。** 公用模式在 root 服务进程中认证，随后用目标 UID、GID 和附属用户组运行独立 `Worker`。私用模式使用服务进程原有身份，包括 root。

攻击者能够控制客户端发送的字段、文件操作顺序和连接频率。开发时应把任何来自网络的字段视为未经信任的数据。

## 2. 私用模式

* 必须配置 `password_file`。连接密码长度为 12 至 1024 字节，文件须为服务账户所属的普通文件，其他用户不能读取或修改；禁止通过符号链接读取密码。
* 服务端可作为非特权用户或 root 运行。root 运行时，远程终端和文件操作拥有 root 权限，必须特别注意开放端口、密码管理与 `file_root`。
* `file_root` 为远程文件访问的目录范围，仍遵循 Linux 文件权限。对 root 而言，Linux 文件权限无法提供额外限制，尤其需要谨慎配置目录和审核代码。

## 3. 公用模式

* 必须由 root 启动服务端。`pam_service` 默认值为 `login`，实际会读取主机的 PAM 配置。
* `auth.py` 调用 PAM 的认证、账号策略、凭据建立和会话相关函数，并在完成后关闭会话。仅在成功通过 PAM 后查询账户及生成对应的 `AuthResult`。
* `server.py` 在创建工作进程时设置 UID、GID 和附属用户组。工作进程首先检查有效 UID，终端、文件操作由该进程负责。
* `LoginRequest.os_login` 由客户端在加密通道提交。独立 CLI 的终端和文件传输均支持此字段。
* 每个文件连接、终端连接分别取得权限；PAM 身份不因客户端 ID、来源地址、其他连接或保存的 RustDesk 共享密码而被复用。

PAM 测试代码通常使用模拟认证函数，同时实际切换 Linux 用户身份。正式部署应额外通过真实 PAM 策略、测试用户和目标发行版验证。

## 4. 官方 GUI 文件登录方式

在客户端发送标准文件传输连接且未携带 `os_login` 时，`file_login.py` 只允许访问虚拟的 `/__rd_login__` 目录：

~~~text
/__rd_login__/
├── USERNAME   重命名为 Linux 用户名
├── PASSWORD   重命名为 Linux 密码
└── LOGIN/     进入此目录提交 PAM 验证
~~~

此阶段不会创建真实目录；只允许读取虚拟目录、重命名两个指定条目及进入提交目录。通过验证后，服务端创建相应用户的文件工作进程。提交失败会清除认证状态，每个连接最多提交四次，默认超时 180 秒。

**重要使用风险：** 官方 GUI 的重命名输入框、客户端文件列表、操作历史或屏幕录制可能显示密码；一些特殊字符不能作为文件名。服务端不会把密码作为文件名返回给客户端。对于生产账号，优先采用 CLI 的隐藏密码输入方式。官方 GUI 的实际显示行为仍需在具体版本上检查。

## 5. 密码与设备身份管理

* `identity_file` 保存设备 ID、随机种子和 UUID，必须保密；它的权限和所有者由程序检查。
* 保存的 RustDesk 连接密码使用设备身份确定的固定 `salt`，每次连接使用新的 `challenge`。设备身份替换后，已保存的密码和客户端固定的设备公钥需要重新配置。
* 不将 `password_file`、`identity_file`、PAM 密码、连接密钥写入 Git、Issues、日志、发布附件或聊天记录。
* `--rendezvous-key` 是命令行参数，可能被本机进程列表或终端历史观察；使用该参数前需评估目标环境的本地用户权限与记录策略。
* 更新或恢复设备时，使用受限的备份渠道保存配置和身份文件。撤销访问时，根据实际情况修改连接密码、重置 PAM 凭据或更换设备身份；相应客户端必须更新连接信息。

## 6. 文件系统与连接访问控制

* `FileWorkspace` 使用目录文件描述符和 `O_NOFOLLOW` 约束路径访问，避免通过符号链接离开 `file_root`。
* 工作进程只能处理当前连接获准使用的功能。未认证的文件会话不能上传、下载或处理终端消息。
* 端口转发默认关闭，开启时使用 `allow_tunnel = true` 与 `tunnel_ports`；仅允许连接 `localhost`、`127.0.0.1`、`::1` 的指定 TCP 端口。
* **公用模式的端口转发不要求 PAM。** 如果本机服务有管理权限或能访问敏感数据，应禁用转发，或使用额外的服务自身认证和 RustDesk 共享连接密码。
* 连接最多 64 个；登录失败按来源地址限制尝试次数。此限制不替代网络层的速率限制、审计或主机防火墙。

## 7. 审查重点与事件处理

优先审查公用模式 root 进程与子进程之间的身份边界、PAM 会话退出清理、未经认证文件操作、文件路径与符号链接、网络消息大小、超时处理、终端命令执行及受限转发。测试和审查结果应更新 [项目台账](PROJECT_LEDGER.md)。

如果疑似发生设备身份或密码泄露，先限制服务器访问并停止受影响服务，再更新相关凭据、重新启动服务、检查系统日志与文件变化。保留调查所需的时间、版本和脱敏日志，不公开任何凭据。当前项目尚未经过完整外部安全审计；生产部署前应完成目标环境的安全检查。
